# Complex state and interaction tests

This optional lesson is for interfaces whose reservation workflow has grown beyond a few independent values.

## Introduce a reducer for related transitions

Use a reducer when many events change related state together. Name events after what happened, not after fields to mutate.

```ts title="reservation-reducer.ts"
type State = { step: 'guest' | 'room' | 'confirm'; draft: Draft }
type Action =
  | { type: 'guest-entered'; guestName: string }
  | { type: 'room-selected'; roomId: number }
  | { type: 'started-over' }
```

Do not add a global store merely because several components exist. Lift state to the nearest shared owner first.

## Test outcomes readers can observe

Test that unavailable rooms cannot be selected, invalid dates show a useful message, submission is disabled while saving, and an API conflict leaves the entered values intact. Query controls by role and accessible name rather than CSS classes generated by shadcn/ui.

The UI components live in your repository, so review changes when re-running the shadcn CLI. Avoid editing every primitive to solve a feature-specific requirement; compose a hotel component around it instead.

## Checkpoint

Write one test for a successful reservation and one for an HTTP `409` room conflict. Each should use the interface the same way a user does.
